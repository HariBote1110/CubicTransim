# v0.1.0-Alpha-9b: 編成中央基準の停車位置

## 課題

Alpha-9a では停車位置を「ホーム奥端基準」にしたが、ホームより長い編成は後方に全部はみ出す挙動のままだった。
ユーザー要望は「編成の中央を基準点にするブレーキ」。ホーム長・編成両数に応じて、編成中央がホーム中央に
最もセル単位で近づく位置に先頭車を止めたい。

## 仕様

停車時の先頭車の停止セルインデックス(ホームセル列に対して、進入順0始まり。entry=進入した最初のホームセル
がindex0)を次式で決める:

```
headIdx = ceil((P + cars) / 2) - 1
```

- P: ホーム長(進行方向に連続する同一stationIdのセル数)
- cars: 編成両数

`headIdx <= P-1` ならホーム内のそのセルで停止。`headIdx > P-1` ならホームを超えて直進方向に線路
(駅セルかどうかは問わない)が存在する限り延長し、線路が尽きたらそこでクランプする(headIdxに届かなくてもよい)。

例:
- P=3, cars=1 → headIdx=1(ホーム中央)
- P=3, cars=3 → headIdx=2(奥端、編成=ホームぴったり)
- P=1, cars=4 → headIdx=2(ホームの2つ先。前後ほぼ均等にはみ出す)
- P=3, cars=4 → headIdx=3(奥端の1つ先)

## 変更1: pathfinding.ts

`RouteQuery` に `cars: number` を追加。`extendThroughPlatform` を全面的に書き換え、
まずホームセル列(P個)を先読みしてから headIdx を計算し、ホーム内で完結する場合とホームを
超えて延長する場合を分けて処理する共通ヘルパー `findNextInLine`(直進方向の次セルを探す、
accept述語で「同一stationId限定」か「任意の線路セル」かを切り替え可能)を抽出した。
ホームの先の線路が足りない場合は `findNextInLine` が null を返した時点でループを止めることで
自然にクランプされる。

## 変更2: simulation.ts

- `computeObstacleDistance`: 目的駅(targetStationId)自身のセルでは障害物としてbreakしない
  ように変更(停止セルがホーム外のこともあるため、目的駅セルの通過だけでは減速判断できない)。
  ループ内で(目的駅以外の)障害物が見つからないまま終わった場合、経路の残り全体を停止距離として
  減速する(経路末尾=編成中央基準の停止セルが停止目標になる)。
- 到着判定を簡略化: 経路を消化しきった(`rt.route.length === 0`)セルで停車する、という単純な
  判定に変更した。従来の「到着セルのstationIdが目的駅と一致するか」という前提は、停止セルが
  ホーム外(stationId無し)のこともある新仕様と矛盾するため撤去した。
- 「既に目的駅にいるので経路探索不要」の判定を、経路探索を呼び出す**前**に
  `rt.lastStopStationId === targetStationId` で行うよう並び替えた。停止セルがホーム外だと
  `rt.prevGrid` が `null` にリセットされているため、経路探索を呼ぶと方向制約が外れて
  BFSが「直前に停車したホームへ戻る」経路(逆方向)を見つけてしまい、Alpha-9aで実装した
  終端反転ロジックが誤発火して無意味な瞬時反転を繰り返す回帰があった。経路探索より前に
  同一駅判定で早期リターンすることでこれを防いだ。

## テスト

- `src/sim/pathfinding.test.ts`: headIdx計算を検証する4件を追加
  (ホーム中央停車、ホーム奥端停車、ホームの2つ先まで延長、線路が足りない場合のクランプ)。
  既存の「ホーム延長は奥端まで」テストは cars=3(P=3ぴったり)に更新し、既存の行き止まりテストは
  クランプ経路(cars=2でホームの先に線路が無い)を通るよう更新した。
- `src/sim/depot-station.test.ts`: シナリオ4・5は stX がホーム1セル・cars=2 のため、
  新仕様ではホームの1つ先(x=2)まで走ってから停車するようになった。停止位置の期待値をx=1→x=2に、
  最初の到着までのtick数を100→150に更新した(移動距離が1タイル分伸びるため)。
- 全169件(既存166件+新規3件)がパス。`npm run build` も成功。

## ブラウザ検証

`localStorage.clear()` の上で `preview_start`(dev)からブラウザを開き、`__debugWorld` を直接
組み立てて(直線線路+駅+編成両数を設定)`__dbgStep(0.1, 200)` でシミュレーションを進め、
`__debugWorld.runtimes` の停止位置を確認した(UIでのドラッグ建設は座標較正に手間がかかるため、
sim層の挙動そのものを検証する目的でこの方法を採った)。

- 3セルホーム(x=2,3,4, stH)+4両編成: P=3, cars=4 → headIdx=3(奥端の1つ先=x=5)が理論値。
  実測結果は `grid.x=5`, `trail=[5,4,3,2]`(status: 'At destination')で理論値と一致。
  編成がホーム(2,3,4)+1セル(5)にまたがって停止する。
- 1セルホーム(x=3, stJ)+2両編成: P=1, cars=2 → headIdx=1(1つ先=x=4)が理論値。
  実測結果は `grid.x=4`, `trail=[4,3]` で理論値と一致。1両目(x=4)と2両目(x=3)の連結部が
  ちょうどホームセル(x=3)付近に来ており、編成中央基準の停車になっていることを確認した。

# 路線(ライン)とダイヤ

## Decision

運用グループを「路線」に昇格させた(v0.3.0-Alpha-6)。Cities: Skylines の路線に近い、
時刻表を持たない「停車駅の並び＋運転間隔＋割り当てた車両」というモデル。

- **運行モード**(`TrainGroupData.mode`)を追加した。
  - `'loop'`: 環状運転。運行表の末尾の次は先頭に戻る(従来の挙動なので既定値)。
  - `'shuttle'`: 折返し運転。終端で向きを反転して来た道を戻る。
    列車は `TrainData.scheduleDirection`(1/-1)で今どちら向きに辿っているかを持つ。
- **乗車判定を「今の片道で停まる駅」に限定**した(`stopsOnCurrentRun`)。
  これで旅客が目的地と逆向きに発車する列車に乗ってしまう問題が消えた。
  折返し運転の終端では、発車と同時に向きが変わるので「折り返した先の全駅」が
  今の片道になる ── 終端で誰も乗れなくなることはない。
- **路線パネル**を作り直した: 運行モードの切り替え、停車駅を順番つきで並べて
  駅ごとの待ち人数を出す、所属列車の一覧と未所属列車のワンクリック割り当て。

## Alternatives considered
- **ゲーム内時計の絶対時刻に発着時刻を割り付ける本格ダイヤ**: 遅延の伝播と
  時刻の再計算が必要で、実装量が数倍になる。運転間隔(headway)方式は
  「団子運転が自然にほどける」という同じ効き目を、はるかに軽い実装で得られる。
- **`stopsOnCurrentRun` の代わりに「全駅を1度ずつ通る並び」を使う**: 折返し運転で
  終端の先まで含んでしまい、逆向きの列車にも乗れてしまう。最初この実装にして
  テストで気づいた。乗車判定に使うなら「向きが変わるまで」で切ること。

## 運転間隔の実績と行き止まりの警告(v0.3.0-Alpha-7)

- **実績の運転間隔**: 発車のたびに「前回同じ駅を発車してからの秒数」を実測して
  路線×駅ごとに直近5件だけ残し(`recordInterval`)、路線全体の平均を
  パネルに「実績 N秒」として出す。設定値(headway)は待ち合わせや信号待ちで
  実際には広がるため、設定値だけでは効いているか分からない。
- **行き止まりの警告**: 環状運転の路線について「終端→始発の回送距離」が
  「路線を一通り走る距離」の0.9倍以上なら、来た道を丸ごと戻っているとみなして
  折返しを勧める(`suggestsShuttle`)。戻る経路が無い場合も勧める。
  自動で切り替えず警告に留めたのは、環状運転を意図している場合を潰さないため。

## Constraints / Gotchas
- `mode` と `scheduleDirection` はどちらも省略可能。旧セーブとの互換のため、
  読み出しは必ず `(g.mode ?? 'loop')` / `(t.scheduleDirection ?? 1)` で行うこと。
- 次の停車駅を決めているのは React 側の `handleTrainArrive`(sim の `arrive`
  イベントを受けて `nextStop` を呼ぶ)。sim 層は `train.scheduleIndex` を読むだけで
  進めない。ブラウザで同期ループを回すと index の更新が反映されないのは このため。
- 環状運転の路線で終端どうしが線路で繋がっていない場合、列車は終端から先頭駅へ
  戻る経路を探して長距離を回送する。行き止まりの路線は折返しにすること
  (v0.3.0-Alpha-7 でパネルが警告するようになった)。
- `suggestsShuttle` は停車駅の数だけ経路探索を回す。描画のたびに呼ぶと重いので、
  GameUI 側で useMemo に包んで「路線・線路・駅が変わったときだけ」計算している。
- 実績の運転間隔(`SimWorld.groupIntervals`)はセーブに含めない。ロード直後は
  「計測中」表示から始まる。

# 旅客の経路検索(行き先つき旅客)

## Decision

「駅を置いただけで人が湧く」のをやめ、旅客に行き先と経路を持たせた(v0.3.0-Alpha-4)。

- **経路は1人ずつ引かない**。出発駅→目的駅ごとに1回だけ探索し、結果を同じ駅ペアの
  旅客全員で共有する(`sim/passengers.ts` の `RouteCache`)。旅客エージェントを個体で
  持つと数千人規模で経路探索が破綻するため。
- **旅客が辿るのは線路ではなくサービス網**。走行中(status='running')の列車の運行表
  (グループ所属ならグループの共有運行表)で隣り合う駅どうしを双方向の辺にする。
  線路が繋がっていても列車が走っていない区間は移動できない。
- **経路の評価軸は「乗換の少なさ」が第一、「駅数の少なさ」が第二**。乗換上限は2回
  (`MAX_TRANSFERS`)で、超える経路しかない駅ペアは「行けない」とみなす。
- **行き先は重力モデルで抽選**。重み = 行き先の集客力(`demandFactor`) ÷ 駅間距離。
  経路の無い駅は候補に入らないため、そこ行きの客は湧かない。
- **待ち客・車内客は行き先つきの塊(コホート)** で保持する。
  - 駅: `SimWorld.demand: Map<駅id, PassengerCohort[]>`。`world.waiting` はその合計を
    写しただけの表示・セーブ用の値になった。
  - 車内: `TrainRuntime.load: OnboardCohort[]`。`alightAt`(目的地または乗換駅)で降り、
    目的地なら乗車駅→降車駅の距離ぶんの運賃、乗換駅ならその駅の待ち客に戻る。
- サービス網と経路キャッシュは、列車の配備状況・運行表・グループが変わったときだけ
  組み直す(`ensureService` が署名文字列を比較する)。

## Alternatives considered
- **旅客を1人ずつのエージェントにする**: Cities: Skylines 的な見た目にはなるが、
  経路探索の回数が人数に比例する。ユーザーの希望もあり「1回の探索を数人で使い回す」
  コホート方式を採用した。
- **所要時間で経路を評価する**: 運転間隔・待ち時間を含めた実所要時間の推定は
  路線ダイヤの実装が前提になるため、今回は乗換回数と駅数に留めた。
- **旧セーブの待ち人数を引き継ぐ**: 行き先の分からない客は運びようがないので、
  v10以前からの移行では待ち客を捨てる(すぐ湧き直す)。

## Constraints / Gotchas
- **列車の進行方向を見ていない**。乗車判定は「経路の最初のlegの系統がこの列車の系統か」
  だけなので、目的地と逆向きに発車する列車にも乗ってしまう(終点で折り返して結局着く)。
  路線に向きの概念を入れるときに直すこと。
- `world.waiting` に直接数字を入れても、もう客は乗らない(行き先が無いため)。
  テストでは行き先つきで仕込むこと(`simulation.test.ts` の `seedWaiting`)。
- 立地需要のテストは「出発地としての集客力」を見るものになった。行き先側にも街が
  必要 ── 行き先に魅力が無いと旅行そのものが発生しない。
- セーブは v11。runtime の `load` と world の `demand` を含む。

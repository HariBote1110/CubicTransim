# デッドロックした列車のドラッグ置き直し

## 決定
- `src/sim/relocate.ts` に `canPlaceTrainAt(world, trainId, headCell)` /
  `relocateTrain(world, trainId, headCell)` を追加した。単線の交換設備で対向列車が
  永久に睨み合う(閉塞ルールそのものが意図した仕様として許すデッドロック、
  `single-track-deadlock-avoidance.md` 参照)を手動で救済する手段。
- `canPlaceTrainAt` は headCell を先頭に、編成長(`train.cars`)ぶんの連続した
  未予約の線路セルを、固定方向順(北→北西の8方向、決定的)で辿って確保する。
  他列車の予約(自分の予約は除く)があれば不可。橋桁(`upper` を持つセル)には
  置けない単純ルールにした(進入方向から層を解決する既存の仕組みと、置き直しという
  「向きの分からない」操作の相性が悪く、誤って橋の下に挟み込むと余計に厄介な
  デッドロックになるため)。
- `relocateTrain` は該当列車の予約をすべて解放し、`trail`/`pathHistory` を
  新しい位置から組み直す(`pathHistory` は既存の終端駅反転処理と同じく、
  `cars+2` 長になるよう最後尾セルで埋める)。`route=[]`・`reservedEndIndex=-1`・
  `speedKmh=0` にして、次の `stepTrain` で経路を再検索させる。
- **`prevGrid` はあえて `null` にする**(妥協点)。`canPlaceTrainAt` が辿った
  trail の向きをそのまま進入方向の制約として引き継ぐと、置いた向きがたまたま
  経路の逆側だった場合、直進しか許さない経路探索(`pathfinding.ts` の
  カーブ制約)が自セルへ戻れず「経路なし」のまま固まることがある
  (統合テストで実際に踏んだ)。`prevGrid=null` はホーム外で方向制約を外す
  既存箇所(`simulation.ts`)と同じ扱いで、置き直し直後だけ無方向探索にする。
- UI側(`GameScene.tsx`)は選択モード(`buildMode==='none'`)でのみ有効。
  ドロップ先の可否は `canPlaceTrainAt` で判定し、建設プレビューと同じ
  緑/赤のセル色で示す。ドラッグ中の `DynamicTrain` は編成をまとめて
  持ち上げて表示し(連結の弧長計算はバイパス)、通常の走行位置計算をスキップする。
- 置き直しは無料(コストを取らない)。救済手段のため。
- `TrainRuntime.waitTimer`(経路待ちの継続秒数)を列車インスペクタに出し、
  60秒以上ならドラッグでの救済を案内する警告文を表示する。

### 操作の起点は地面プレーンに一本化する(列車メッシュの pointerdown には依存しない)
- 最初の実装(`811a5fb`)は「列車メッシュの `onPointerDown` → 地面の
  `onPointerUp` で決着」という方式にしていた。これは**選択モードで列車を
  クリックしても選択できなくなる不具合**を生んだ(`onPointerDown` を握る
  列車メッシュ自体が拾えない/発火しないケースに、クリック選択もろとも
  依存してしまっていたため)。
- 修正: `DynamicTrain` の選択は元の `onClick` 方式に戻した
  (`onClick={() => buildMode==='none' && onSelectTrain(train.id)}`、
  ドラッグ直後の余計な選択だけ `justDraggedRef` で1回だけ無視する)。
  ドラッグの開始は **地面プレーンの `onPointerDown`** に一本化し、押下した
  セルに列車がいるかを `sim/relocate.ts` の `trainAtCell(world, cell)`
  (`TrainRuntime.trail` を線形走査するだけの純粋関数、`relocate.test.ts`
  でテスト済み)で判定する。別セルへ動いた時点でドラッグへ昇格させる
  考え方(クリック選択と競合させないための閾値)はそのまま維持した。
  `DynamicTrain` の `onPointerDown` prop は不要になったため削除した。
- 教訓: 「同じ操作(掴む/選ぶ)の起点を、対象オブジェクト側のイベントと
  地面側のイベントに分けて持たせる」設計は、r3f のレイキャストが対象
  オブジェクトを拾えない場合(高さのある3Dオブジェクトの見た目上の位置と、
  地面平面との交点セルがずれるアイソメトリック視点では特に起きやすい。
  実機確認時にも「列車の見た目の位置をクリックしても地面の交点セルは
  1マスずれる」現象を実際に踏んだ)に、選択そのものが機能しなくなる
  単一障害点になる。操作の起点は常に1つの安定したイベントソース
  (今回は地面プレーン)に統一し、対象の判定はそこから `trainAtCell` の
  ような純粋関数で行うほうが安全。

## 妥協した点
- 編成の向き(trailの辿り方)は「固定方向順で最初に見つかった連続セル」を
  機械的に選ぶだけで、実際にどちらが自然な向きかは考慮していない。
  そのため `prevGrid=null` にして経路探索の方向制約自体を外している
  (上記)。将来、置いた位置から両方向に経路が引けるケースで意図と違う
  方向へ発進する可能性はあるが、次のtickで経路が見つかりさえすれば
  デッドロックからは脱出できる。
- 立体交差(橋)は「置けない」の一言で片付けている。橋の上下どちらへ置くか
  をユーザー操作から一意に決める手段が無いため。

## 実機確認について
- sim層は `src/sim/relocate.test.ts`(9件、`trainAtCell` のテストと
  `stepWorld` を使った統合テスト込み)で、置き直し後に実際に経路が
  再検索されて列車が動き出すことまで確認済み。
- ブラウザでの実機確認(このセッションで完了): `window.__debugWorld` を
  直接組み立てて保存データ(localStorage の `cubictransim-save-v1`)へ書き込み、
  読込ボタンで React state に反映させたうえで、実際のポインタ操作(hover→
  left_click / left_click_drag)で検証した。
  - 選択モードで列車をクリックすると選択され、インスペクタに列車情報
    (`列車 t1` / 運行中 / 編成など)が表示されることを確認した。
  - 列車を別の線路セル(grid (0,0) → (4,0))へドラッグすると、
    `world.runtimes.get('t1').trail` が `[{4,0},{5,0}]` に変わり、
    画面上の描画位置も新しい位置へ移ることを確認した。
  - クリック座標の割り出しに手間取った(等角投影のカメラでは、地面
    プレーンとの交点セルが列車の見た目上の位置から数十px・1マス弱ずれる。
    これは今回の不具合そのものの背景でもある)。最終的には一時的な
    デバッグ用ログ(コミットはしていない)で `e.point` の実測値を見ながら
    座標を追い込んだ。

# v0.1.0-Alpha-9a: ホーム全体基準の停車位置と終端駅での瞬時反転

## 課題

1. **停車位置が先頭車基準だった**: `calculateRoute` は目的駅のセルにBFSが最初に到達した時点で経路を確定していたため、
   複数セルからなるホーム(同一stationIdの連続セル)であっても先頭車は手前のセルで止まってしまい、
   後続車がホームから大きくはみ出す挙動になっていた。
2. **折り返し時に編成が「めり込む」ように反転していた**: 終端駅で折り返す際、後続車が先頭車の経路(trail)を
   逆走する形で追従するため、描画上は編成が自分自身を通り抜けるように見えるバグがあった。

## 変更1: ホーム奥端までの経路延長

`src/sim/pathfinding.ts` の `calculateRoute` に `extendThroughPlatform` を追加。BFSが目的駅セルに到達した時点で
経路を確定するのではなく、そこから進行方向へ直進(急カーブ制約: 内積>=0.5)する接続を辿り、
**同一stationIdのセルが続く限り**経路を延長する。分岐がある場合は最も直進に近い(内積が最大の)候補を優先し、
延長できる候補が無くなった時点で経路を終える。単一セルの駅(既存の全テストが使う形)は延長候補が無いため
従来通りの挙動のまま変わらない。

`src/sim/simulation.ts` の到着判定(`keepGoing`)も、従来の「駅中心からの距離比較」から
「次の経路セルが同一駅なら通過し続ける」という単純な判定に置き換えた。経路(pathfindingで既にホーム奥端まで
延長済み)が尽きたセル=ホーム奥端で停車するようになる。

結果として、編成はホームの奥端まで進んでから停車し、後続車がホーム上に載るようになった
(ホーム長 < 編成長のときは後方がはみ出すが、これは既存のホーム長ペナルティの仕様と整合する)。

## 変更2: 終端駅での瞬時反転

`stepTrain` の経路再探索箇所(`rt.route.length === 0` で新しい経路を取得する場所)で、取得した経路の
最初の移動方向が「折り返し」かどうかを判定する:
- `newPath[0]` が反転前の `rt.trail[1]`(自編成の2両目のセル)と一致する(自分の中に経路が伸びようとしている)、または
- 到着時の進行方向(`rt.prevGrid -> rt.grid`)と新しい発車方向の内積が負(逆走)

いずれかに該当すれば、発車前に編成を瞬時に反転する:
- 新先頭セル = 旧 `trail` の末尾(旧最後尾)
- `trail` を反転
- `pathHistory` は反転した `trail` を先頭に据え、末尾セルの複製で `carCount+2` まで埋め直す
  (**設計判断**: 指示では単純に `pathHistory` も反転するとされていたが、`pathHistory` は `trail` より
  長め(carCount+2)に旧方向へ延びた履歴を含むため、そのまま全体を反転すると新先頭の手前に
  「反転前の延長分」が逆順で挿入され、`carPositions` の弧長サンプリングが新先頭から一度奥へ戻ってまた
  戻ってくるようなジグザグ軌跡になり、発車直後の車間が破綻する。これを避けるため、反転後の
  `pathHistory` は「反転した `trail` + 末尾セルの複製によるパディング」で組み直す。見た目の結果は同じく
  瞬時反転だが、直後の car spacing が壊れない)
- `rt.grid`/`rt.prevGrid`/`rt.progress`/`rt.renderPos`/`rt.renderTarget` を反転後の状態に更新
- 反転後の新しい先頭位置から経路を再探索する

## テスト

- `src/sim/pathfinding.test.ts`: ホーム(同一駅IDの連続セル)は奥端まで経路を延長するテスト、
  および行き止まり(延長候補なし)では従来通り最初の到達セルで止まるテストを追加。
- `src/sim/simulation.test.ts`: 3セル連続ホームでホーム奥端に停止するテスト、および終端駅での
  瞬時反転(新先頭=旧最後尾、発車直後の連続tickで車間が常に一定、その後A駅に到着する)テストを追加。
- `src/sim/depot-station.test.ts`: シナリオ3・5は schedule=[stX,stY] が巡回するため、固定tick数で
  打ち切ると停車完了後にすぐ反転・折り返し発車してしまい得るようになった(改善前は折り返しに
  非常に時間がかかっていたため固定tick数で問題にならなかった)。到着/停車完了の瞬間で打ち切るように
  アサーションの意味を保ったまま更新した。

テストは既存162件+新規4件=166件、全てパス。`npm run build` も成功。

## ブラウザ検証

`localStorage.clear()` からブラウザ上で depot・3セルホーム駅・4両編成を構築し、`__dbgStep`/`__debugWorld` で
シミュレーションを直接進めて確認した:
- 4両編成が3セルホームに進入すると、先頭車がホーム奥端まで進んでから停車し、編成がホームに沿って並ぶ
  (4両>3セルのため最後尾1両がホームからはみ出すのは仕様通り)。
- 2駅間(Station A ⇔ Station B)を往復させると、Aで停車後の発車時に編成が瞬時に反転し(新先頭=旧最後尾)、
  めり込み・重なりなく逆方向へ走行してBへ到着する。

なお、UI操作(ドラッグでの線路敷設)は本ブランチの検証時点でも画面クリック座標のブレが大きく、
线路建設のドラッグ操作の座標合わせに手間取った。ワールド→スクリーンの正確な変換式は
`terrain-and-construction-constraints.md` に記載の近似式(`screenX ≈ 355 + 15*(x-z)`,
`screenY ≈ 234.5 + 8.5*(x+z)`)だけでは実際のズームレベル・カメラ状態次第でずれることがあるため、
今回は実測(既知の1点をクリックしてマッピングされたセルを`__debugWorld`で確認し、そこから
線形パラメータを逆算する)によって補正した。今後同種の検証を行うエージェントは、
固定式を過信せず、まず1回のクリックで実際のセルを確認してから残りの座標を逆算するとよい。

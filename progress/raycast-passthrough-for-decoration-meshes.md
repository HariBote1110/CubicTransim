# 装飾・線路メッシュのレイキャスト透過(高架下の駅設置不具合)

## 不具合

高架(`upper`)の桁・レール・支柱・橋台のメッシュ(`TrackNetwork`)がreact-three-fiberの
レイキャストを受け取ってしまい、その真下の地平セルへクリックが届かなかった。
地面プレーン(`GameScene.tsx`のクリックハンドラ一式)は常に地平の`y=-0.02`平面にしか
無いため、上に何か不透明なメッシュがあるとそちらが先にヒットし、`onClick`/`onPointerDown`
等が地面まで貫通しない(react-three-fiberはヒットしたオブジェクトから祖先へイベントを
バブルさせるが、地面プレーンはそのメッシュのイベントハンドラでしか発火しないため、
別のメッシュがヒットすると地面のハンドラは呼ばれない)。

結果として、地平の線路を高架が跨ぐ交差点では:
- `3`(地平駅)キーでクリックしても地面のクリックハンドラに届かず、駅が置けない
- `8`(高架駅)キーの設置もカーソル位置(=地面へのレイキャスト)で決まるため、同様に置けない

「立体交差の十字乗換駅」(地平ホーム+高架ホームを同じセルに重ねる)という中心的な操作が
全くできなくなっていた。

## 決定

`GameScene.tsx`のクリック判定はすべて地面プレーン(`onPointerMove`/`onPointerDown`/
`onPointerUp`/`onClick`)の1箇所に集約されており、駅・車庫・信号・列車ラベルなどの
描画専用メッシュは元々「クリックして選ぶ対象」ではない(選択は地面のクリック位置から
セル座標を求め、railMap/stations/trainAtCellへ問い合わせて判定している)。
列車(`DynamicTrain`)だけが車両グループに独自の`onClick`を持ち、選択対象として機能する。

そのため、以下のように「選択対象ではないメッシュ」全てに`raycast={() => null}`を設定し、
レイキャストを常に素通しにした:

- `TrackNetwork.tsx` — 線路・高架桁・支柱・橋台(本件の直接の原因)
- `RailBlock.tsx` — 建設プレビュー用の単セル線路
- `StationBlock.tsx` — ホーム床・側壁・点字ブロック・上屋・柱・ホームドア、および`StationHouse`(駅舎)
- `DepotBlock.tsx` — 車庫の外観一式
- `SignalBlock.tsx` — 信号機一式
- `Scenery.tsx` — 樹木
- `TerrainBlocks.tsx` — 水域・山岳の装飾
- `TownBlocks.tsx` — 街の建物(ラベルは元々`pointerEvents:'none'`のHTML)
- `GameScene.tsx` — 建設プレビューの半透明ボックス、列車ドラッグの置き先プレビュー、橋・トンネルの装飾メッシュ
- `DynamicTrain.tsx` — 選択中マーカー(コーン)・経路スフィア(選択用の`onClick`は車両グループのみに残す)

列車本体(`TrainCar`)のメッシュは意図的に変更していない。選択の`onClick`は
`DynamicTrain`内の車両グループに付いており、react-three-fiberはヒットした
子孫メッシュから祖先へイベントをバブルさせるため、`TrainCar`側のメッシュは
レイキャスト対象のままにしておく必要がある。

## 代替案

- 地平の地面クリックとは別に、各メッシュに個別の`onClick`を持たせて選択ロジックを
  分散させる案は採らなかった。既存の選択ロジック(セル座標からrailMap/stationsを
  引く方式)を壊さずに直せるため、レイキャストを外すだけの変更に留めた。

## 実機確認(2026-07-28)

Browserツールで`preview_start`→地平線路(`2`)と高架(`7`)を直交させて交差セルを作成:

1. 交差セルに`3`で地平駅を設置 → 成功(`railMap`の該当セルが`type:'station'`に変化、課金あり)
2. 同じ交差セルに`8`で高架駅を設置 → 成功(`upper.stationId`が同じ駅IDに統合)
3. `window.__debugWorld.stations`で該当駅の`cells`に`layer`なし(地平)と`layer:1`(高架)の
   2セルが入っていることを確認
4. `1`(選択)で交差セルをクリックし、駅の詳細パネル(青木駅)が開くことを確認
5. 車庫を新設して列車を購入・運行表に同じ駅を追加・出庫まで成功することを確認
   (`status`が`stored`→`running`に変化)。ただし手作業で敷いた試験用の線路網が
   車庫と本線を繋ぐ直線区間を欠いていたため、経路探索が`Waiting for Path...`で
   止まる状態までしか確認できていない。これは本修正(レイキャストの透過)とは無関係な、
   試験用に即席で敷いた線路網のトポロジー不備であり、選択・購入・運行表編集・出庫という
   クリック操作の一連の流れ自体は問題なく動作した。

`npm run test`・`npm run build`はともに成功。

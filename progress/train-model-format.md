# 列車モデル制作仕様(外部エージェント向け・自己完結)

CubicTransim の列車 3D モデルを制作するための完全な仕様。この文書だけを読めば、
リポジトリを見ずにモデルを納品できることを目的とする。

## 納品物

- **glTF 2.0 バイナリ(.glb)1ファイル = 1車種**(例: `commuter.glb`, `express.glb`)
- Blender からのエクスポートを想定(他ツールでも glTF 2.0 準拠なら可)
- 配置先: `public/models/trains/<車種id>.glb`(車種idは小文字英数とハイフンのみ)

## 座標系・単位(最重要)

- glTF 標準座標系: **+Y が上、右手系**
- **前方 = +Z**(車両の顔・運転台が +Z を向く)
- **単位: 1.0 = ゲームの1セル**(= 線路1マス分。メートルではない)
- **原点 = 車両の平面中心、y=0 = レール上面**(車輪がレールに接する高さ)。
  ゲーム側が原点をレール上面のサンプル点に置き、ヨー(進行方向)とピッチ(勾配)を
  原点まわりに適用する。y=0 を跨いで下に出るジオメトリは禁止(フランジ表現も y≥0 に収める)

## 寸法制約

| 項目 | 値 |
|---|---|
| 全長(Z) | **≤ 0.92**(推奨 0.86。連結間隔が 1.0 固定なので、これを超えると隣の車両と接触して見える) |
| 全幅(X) | **≤ 0.50**(推奨 0.44。バラスト幅 0.5 に収める) |
| 全高(Y) | **≤ 0.60**(レール上面から。パンタグラフ含む) |
| 台車位置 | 車体中心から前後 **±0.35** 付近に台車・車輪を置く(勾配でのピッチ回転が自然に見える基準点) |

参考: 現行のプレースホルダ車両は 全長0.86 × 全幅0.44 × 車体高0.25(+屋根上機器)。
これより極端に大きい/小さいとゲーム内で浮く。

## ノード構成(命名規約)

シーン直下に以下の名前のノードを置く。それぞれ1つの静的メッシュ(子ノード階層は
可だが、インポート時に全て焼き込みで平坦化される):

| ノード名 | 必須 | 用途 |
|---|---|---|
| `car_head` | ✔ | 先頭車(+Z が顔)。編成の先頭・最後尾に使われる(最後尾は180°回転で流用) |
| `car_mid` | ✔ | 中間車 |
| `car_tail` | 任意 | 最後尾専用形状が必要な場合のみ(無ければ `car_head` の回転流用) |
| `car_head_lod1` / `car_mid_lod1` / `car_tail_lod1` | 任意 | 遠景用低ポリ版(**≤ 80三角形**、シルエット重視) |

上記以外のルートノードは無視される(作業用オブジェクトは削除してから出力すること)。

## ジオメトリ制約

- 三角形数: **1車両 ≤ 500**(推奨 200〜350)。1000編成×8両を同時描画するため厳守
- **スキン・アニメーション・モーフ禁止**(全て静的メッシュ)
- 法線は含めてよい(平面シェーディング前提。スムーズシェード指定は無視され、
  面単位の簡易ランバート陰影がゲーム側で焼かれる)
- UV・テクスチャ・画像は**禁止**(v1 はフラットカラーのみ)

## マテリアル(色)

- 色は各マテリアルの `baseColorFactor`(フラットカラー)のみ使用。
  metallic/roughness/emissive/透明度は無視される(不透明として扱う)
- マテリアル数は自由(インポート時に頂点色へ焼き込まれる)
- **マジックマテリアル名**(この名前を付けると実行時に特別扱いされる):
  - `line_colour` — **路線色**。この名前のマテリアルが付いた面は、実行時にその編成の
    路線カラーで塗り替えられる(帯・ラインに使う。baseColorFactor は何色でもよい)
  - それ以外の名前は自由(色はそのまま使われる)
- ヘッドライト・テールライトは光らない。明るい色/赤色の面として `car_head` に
  直接モデリングする(前面 = ライト白、背面 = 赤、が180°回転流用で丁度良くなる)

## 色調ガイド(ゲームの雰囲気に合わせる)

- ローポリ・ジオラマ調。彩度は中〜低め、パステル寄り
- 参考パレット: 車体 `#e8e4dc`、屋根 `#9aa0a6`、窓 `#2f3a44`、スカート `#6b7076`、
  台車 `#3c4046`
- 窓は面を少し凹ませる(または濃色面)だけでよい。透過表現は不要

## バリデーション

納品前に以下で自己検査できる(リポジトリの `renderer/tools/validate_train_glb.mjs`。
R4c 実装後に利用可能):

```bash
node renderer/tools/validate_train_glb.mjs public/models/trains/<車種id>.glb
```

検査項目: glb 2.0 として解析可能 / 必須ノード(`car_head`, `car_mid`)の存在 /
三角形数上限 / バウンディングボックス(寸法制約) / y<0 ジオメトリなし /
テクスチャ・スキン・アニメーション不使用。

## ゲーム側の扱い(参考情報)

- 編成は 1〜8 両、車間 1.0(セル)固定。各車両は線路のベジェ中心線上の点に置かれ、
  ヨー+ピッチが適用される(ロールなし)
- 地下では減光、遠景ズームでは LOD1(あれば)またはドットに切り替わる
- レール上面はセル基準高さ +0.13。モデルの y=0 がそこに接地する
- 車種 id はゲーム内の列車タイプ選択と対応する(登録は開発側で行うので、モデル制作者は
  .glb を納品するだけでよい)
- 実行時の車体原点はレール上面より `RAIL_SUPPORT_OFFSET`(0.37, src/render/trainInstanceMath.ts)
  だけ高い位置にある(手続き生成メッシュがy=-0.37まで伸びて車輪をレールに接地させているため)。
  `trainModelLoader.ts` の `bakeNode` はglb焼き込み時に全頂点をy -= RAIL_SUPPORT_OFFSETし、
  この節の「y=0=レール上面」という作画規約を実際の接地面に一致させている
  (修正前はこの相殺が無く、外部.glbモデルがレールより0.37浮いて表示される不具合があった)

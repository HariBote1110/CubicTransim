# v0.3.0-Alpha-1: 停車挙動の作り直しと、ジオラマ風の描画・GUI全面改修

## 1. 停車の不自然さの解消（sim層）

### 1-1. 症状と原因

「駅に近づく時の減速がぎこちない」「停車位置がセル中心固定でホームとずれる」の2点を扱った。

**減速がぎこちない**問題の原因は、制約が3つ重なって互いを打ち消していたこと。

| 制約 | 出どころ | 副作用 |
| --- | --- | --- |
| `sqrt(2ad)` の許容速度包絡線 | v0.1.0系 | ブレーキが0から一定値へ階段状に立ち上がる |
| `cur_speed − delta_v/10` と `25×残りセル数` の線形床 | v0.2.0-Alpha-2b（OpenTTD原式の移植） | sqrtカーブと競合して減速が段付きになる |
| `STATION_APPROACH_MIN_KMH=15` / `MIN_CRAWL_SPEED_KMH=5` の最低速度床 | v0.2.0-Alpha-2c | 停車の最後で速度が 5km/h → 0 へ飛ぶ |

そもそも最低速度床が必要だったのは、線形床（`v ∝ 残り距離`）が終盤で支配的になると
時間軸では指数的漸近になり、停止直前に延々と這い続けてしまうため。つまり
「OpenTTDのヒューリスティックを入れた → だらだらクロールが出た → 速度床で潰した →
最後にカクッと止まるようになった」という連鎖だった。

さらに、`BRAKING_MARGIN_M=0.5` を駅の停止位置にも適用していたため、列車は
理論上は停止位置の 0.5m 手前へ漸近するだけで到着判定に届かず、これも最低速度床に
依存していた。

**停車位置のずれ**は量子化が原因。停止セルを `headIdx = ceil((P+cars)/2) − 1` と
切り上げていたため、`P + cars` が奇数のときは編成が常に半セル（= 15m）ホーム奥へ寄っていた。

### 1-2. 対応

**制約をジャーク制限つきの制動曲線1本に統一した**（`sim/physics.ts`）。

```
permittedSpeedKmh(d, a, j, currentDecel):
  k = (a − currentDecel) / (2j)          // まだ込めていない減速度の立ち上げに要する時間
  v = a·( sqrt(k² + 2d/a) − k )          // d = v²/(2a) + v·k を v について解いたもの
```

- ブレーキ緩解中（`currentDecel = 0`）は最大の余裕を見るのでブレーキ開始が早まり、当たりが柔らかくなる
- 込め終わり（`currentDecel = a`）では `k = 0` となり `sqrt(2ad)` に一致する。
  ここが重要で、終盤に `k` が残ると `v ∝ d` の線形則になり、旧実装と同じだらだらクロールに戻る
- 逆関数 `brakingDistanceM(v, a, j) = v²/(2a) + v·a/(2j)` も切り出し、速度制御と
  PBS予約の延長判定で**同じ制動距離**を使うようにした（後述の落とし穴の対策）

実際の減速度も `rampDecel()` でジャーク制限（`BRAKE_JERK_MS3 = 6.0 m/s³`、
`DECEL_KMH_S = 20km/h/s` を約0.9秒で込め切る値）をかけている。

**制動はサーボ制御にした**。「常に常用最大で込める」のではなく、停止点でちょうど0に
なるのに必要な減速度 `aReq = v²/(2d)` を目標にジャーク制限つきで追従させる。
最大で込め切ると必要以上に減速して停止点の手前で失速し、そこから包絡線に沿って
這い直すことになる（＝だらだらクロールの再発）。

**ブレーキ指令はラッチする**（`rt.braking`）。しきい値と実速度が毎tick交差して
込める／緩めるを繰り返すと速度が脈動するため、一度制動に入ったら見通しが
`BRAKE_RELEASE_MARGIN_KMH = 3km/h` ぶん伸びるまで緩解しない。

**停止位置はサブセル精度にした**（`sim/pathfinding.ts` / `sim/simulation.ts`）。
`calculateRouteWithStop()` が経路に加えて `stopProgress`（最終区間内の停止位置、0<f≤1）を
返す。`headPos = (P + cars)/2 − 1` の端数をそのまま `stopProgress` に載せるので、
`P + cars` が奇数でも編成中央とホーム中央が一致する。

- 端数停車すると `rt.progress` は**負値**（セル中心の手前）になる。発車時はこの値から
  動き出すので、描画位置が跳ねずに滑らかに走り出す
- `carPositions()`（`sim/consist.ts`）は `renderPos` が `pathHistory[0]` より後方に来る
  ケースを扱えるようにした。先頭が前進→後退と反転しているポリラインの折り返し点を
  落とさないと、弧長サンプリングが破綻して後続車が前へめり込む

`BRAKING_MARGIN_M` は信号・予約末端にだけ適用し、駅の停止位置には適用しない。
代わりに `ARRIVAL_SNAP_M = 0.05`（1セル30mに対し0.17%）のスナップを安全網として置いた。

### 1-3. 踏んだ落とし穴（重要）

**PBS予約が永久に延長できなくなるデッドロック。**
`ensureReservation()` の延長条件が `remaining > brakingDistance + BRAKING_MARGIN_M` で、
制動距離を `sqrt(2ad)` 前提の `v²/(2a)` で計算していた。新しい速度制御は常にその
外側（＝より手前で減速する包絡線）を走るため、`brakingDistance` が常に
`remaining − マージン` より小さくなり、条件が**永久に成立しない**。予約末端の直前で
停止したまま二度と延長できなくなった。

旧実装ではこれが表面化しなかったのは、最低速度床（5km/h）のおかげで制動距離が
常に 0.97m 以上あり、たまたま条件を跨げていたため。速度床は
「クロール防止」だけでなく「予約延長のトリガ」も兼ねてしまっていた。

対策は2つ:
1. 予約延長の判定でも速度制御と同じ `brakingDistanceM()` を使う
2. 予約末端で完全停止した状態（制動距離0・残距離=マージン）からでも必ず再試行できるよう
   `RESERVE_EXTEND_SLACK_M = 1.0` の下駄を履かせる

**計測結果**（15セル直線、dt=1/60、停車まで）:

| | 旧 | 新 |
| --- | --- | --- |
| 10km/h未満の滞在 | 約8秒 → 1.33秒（Alpha-2cで短縮） | 0.6秒 |
| 停車直前の速度 | 5.0km/h（床）から0へ飛ぶ | 1.2km/h |
| 減速度のジャーク | 階段状（無制限） | 30 km/h/s² 以内 |
| 編成中央とホーム中央のずれ | 最大0.5セル(15m) | 1cm以内 |

回帰テストは `sim/station-approach.test.ts`（プロファイル）と
`sim/stop-position.test.ts`（停止位置・端数停車からの発車）に置いた。

## 2. ローポリ鉄道模型風の描画

「Nゲージのジオラマ」を目標に、描画層を全面的に作り直した。**sim層のデータ構造は一切変えていない**
（地形は水域/山岳の2種のまま、標高は導入していない）。描画専用のモジュールは `src/render/` に置いた。

- `render/palette.ts` — 配色と共有マテリアル。セル数が多いのでマテリアルは必ず使い回す
- `render/trackGeometry.ts` — バラスト・枕木・レールのジオメトリ生成
- `render/mergeGeometry.ts` — ジオメトリのマージ（後述の落とし穴あり）
- `render/groundTexture.ts` — 草地の色ムラ（Canvasで生成、外部アセット不要）

| 対象 | 旧 | 新 |
| --- | --- | --- |
| 線路 | レール2本のみ | バラスト＋枕木＋レール。`TrackNetwork` が線路網全体を3ドローコールにマージ |
| 駅 | オレンジの箱1個 | ホーム床・側壁・点字ブロック・上屋・柱・ホームドア・駅舎。線路の向きに合わせて回転 |
| 車両 | 白い箱1個 | 台車・床下機器・車体・側窓・ラインカラー帯・屋根・クーラー・前面（前照灯／尾灯）。先頭/中間/最後尾で作り分け |
| 地形 | 半透明の青タイル／灰色の四角錐 | 掘り下げた水面＋砂色の岸、座標ハッシュで形を散らしたローポリの岩塊（高所には雪冠） |
| 平地 | 単色 | 草地テクスチャ＋樹木（`Scenery`。座標ハッシュで決定的に生成する純粋な描画要素） |
| 街 | 灰色の箱 | 中心ほど高層、低層は寄棟屋根、高層はパラペットと屋上設備 |

### 描画で踏んだ落とし穴

**1. `mergeGeometries` の index 混在。**
`BoxGeometry`/`ConeGeometry`/`CylinderGeometry` は index 付き、
`OctahedronGeometry`/`IcosahedronGeometry`（多面体系）は index 無し。混ぜると
黙って `null` が返り、コンソールにエラーだけ出て何も描画されない。
`render/mergeGeometry.ts` の `mergeAndDispose()` で必ず非index化に揃えてから合成する。

**2. `shadow-camera-*` を宣言的に書いても効かない。**
react-three-fiber は `shadow-camera-left` 等を設定しても `updateProjectionMatrix()` を
呼ばないため、シャドウカメラが既定の±5のままになる。原点付近のごく狭い範囲にしか
影が出ず、事実上「影が消えている」ように見える。ref経由で設定して明示的に
`updateProjectionMatrix()` を呼ぶこと（`GameScene.tsx` の `SunLight`）。

**3. 光源の位置。**
カメラは `(20,20,20)` から原点を見ている。光源を同じ側（+x,+y,+z）に置くと影が
物体の裏側＝画面上で物体自身に隠れる位置へ落ちるため、影が出ていても見えない。
`-x` 側から差す横光 `(-30, 34, 14)` にして、影が画面右下方向へ伸びるようにした。

**4. `<Environment preset="...">` は外部HDRを取りに行く。**
オフラインや制限環境では `Could not load ...hdr` で失敗する。半球光＋平行光で
十分な絵が作れるので撤去した。

## 3. GUIの全面改修

- **デザイントークンを `src/ui/theme.ts` に集約。** これまで各所にインラインstyleを
  直書きしており、角丸・余白・配色・フォントサイズがコンポーネントごとにばらついていた。
  「明るいジオラマの上に載る暗いガラスのパネル」というトーンに統一した
- **表記を日本語に統一。** Rail/Station/Depot/Signal/Remove → 線路/駅/車庫/信号/撤去。
  新規駅の採番も `Station A` → `A駅` 形式にした（旧セーブの駅名はそのまま保持される）
- **上部ツールバーを整理。** 一列に詰まっていた速度・日付・Finance・Save/Load・停車位置を、
  中央（時間）／右上（収支・設定・保存・読込）に分離し、ゲーム全体設定である
  停車位置（手前/中央/奥）は設定パネルへ移した
- **建設のコスト・可否フィードバックを追加。** ドラッグ中にツールバー上へ
  「線路 9マス ¥900」のように出る。橋・隧道のセル数も内訳表示する。
  資金不足なら「資金が足りません」、水域への駅など建設が成立しない場所では
  「ここには建設できません」と出る
- **判定ロジックはsim層に置いた**（`sim/buildPreview.ts`）。UI側に条件を書き写すと
  本体のルール（水域・山岳のno-op、上書き防止）とずれていくため、
  `construction.ts` の apply系が「変化が無ければ同じ参照を返す」性質を使い、
  実際に適用してみた結果から可否を判定する
- **キーボードショートカット。** 1〜6 で建設モード、Space で一時停止、Esc で選択解除
- **`index.css` のViteテンプレート残骸を撤去。** ダーク配色、`body` の flex/place-items、
  `button` の独自配色が全画面キャンバスのUIと噛み合わず、パネル位置とボタンの
  見た目を崩していた

## 4. 既知の課題（未対応）

- **単線での正面デッドロック。** 交換設備の無い単線区間で対向列車が向かい合うと、
  PBS予約が互いを塞いで恒久停止する。**この挙動は本変更の前後で同一**（v0.2.0-Alpha-2c の
  コードでも同じシナリオで同じ位置に停止することを確認済み）なので本変更による退行ではないが、
  待避可能地点まで戻る／進入前に単線区間全体を予約する等の対策が別途必要
- **斜めの終端駅からの折り返しに失敗することがある。** 例: `(11,1)`–`(12,0)` の斜め2セル駅を
  終端にすると `Waiting for Path...` のまま発車できない。これも本変更の前後で同一
